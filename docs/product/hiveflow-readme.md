# HiveFlow

从策略出发，做更清晰的决策

## 产品一句话

HiveFlow 是一个由多策略协作驱动的个人资产决策系统，帮助用户基于真实持仓、策略判断和资金分配，做出更清晰的投资决策。

## 为什么做

这个项目最初来自一种长期不稳定的使用方式：

- 写一个很大的 Skill
- 通过对话问 AI 买什么、用什么策略、回测怎么样
- 在聊天里不断纠正 AI 的理解

这种方式短期可用，但长期会出现明显问题：

- AI 给出的数据和真实持仓、真实策略状态容易对不上
- 用户需要重复解释自己的偏好和约束
- 当下纠正有效，但过几天系统又像从头开始
- 分析很多，但缺少一个稳定、可核对的状态底座

因此，HiveFlow 不是为了“让 AI 更会说”，而是为了建立一个可以承接真实数据、用户纠正和长期决策记录的系统。

在这个系统里，策略和持仓的关系需要保持清楚：

- 策略负责生成当前动作和目标持仓
- 目标持仓是策略在当前时点给出的理想配置结果
- 实际持仓是账户当前真实持有的状态
- 产品通过比较目标持仓和实际持仓，判断是否需要调整

## 它解决什么问题

HiveFlow 主要解决四个问题：

1. 用户需要一个地方查看真实状态，而不是只在对话里听 AI 描述
2. 用户的偏好、纠正和决策结果需要被沉淀，而不是留在临时聊天里
3. 多策略分析需要被组织成一条清晰的决策主线，而不是零散建议
4. 资产不只是选标的问题，还包括风险判断、持仓对齐和资金配比

换句话说，HiveFlow 要持续帮助用户回答：

1. 现在看什么
2. 现在信哪个策略
3. 现在要不要动
4. 现在持仓和资金配比要不要调整

## MVP 核心闭环

第一版先不追求完整形态，也不急着接入 AI。

MVP 只先打通最小闭环：

1. 管理可用策略和基础回测结果
2. 记录真实持仓和账户状态
3. 查看当前每一支持仓及其风险水位
4. 查看当前整体资产配比
5. 生成当前策略目标持仓
6. 对比实际持仓与当前策略目标持仓
7. 给出调仓、资金分配和处理优先级建议
8. 记录用户的确认、修正和关键偏好

第一版先把系统的地基打稳：

- 策略池
- 策略席位
- 持仓状态
- 单标的风险水位
- 资产配比状态
- 资金分配规则
- 风险判断
- 决策日志

## 一句话总结

HiveFlow 不是一个“问 AI 买什么”的工具，而是一个把策略、风险、仓位和资金分配组织成稳定决策流程的个人资产决策系统。
