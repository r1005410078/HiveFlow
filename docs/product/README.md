# 产品文档说明

这个目录保存 `蜜蜂 / HiveFlow` 的核心产品文档。

这些文档不是并列重复的，它们各自回答不同问题。

## 阅读顺序

建议按下面顺序阅读：

1. `hiveflow-readme.md`
2. `product-philosophy.md`
3. `product-positioning.md`
4. `mvp-requirements.md`
5. `product-design-plan.md`
6. `strategy-taxonomy.md`
7. `../skills/README.md`

## 每份文档是做什么的

### `hiveflow-readme.md`

这是产品总纲。

主要回答：

- HiveFlow 是什么
- 为什么要做
- 它解决什么问题
- 第一版的大致核心闭环是什么

如果只看一份文档，先看这一份。

### `product-philosophy.md`

这是产品理念文档。

主要回答：

- 为什么 HiveFlow 不只是一个 AI 工具
- 为什么不能只靠对话和临时分析
- 为什么真实状态层、记忆层和决策日志很重要
- HiveFlow 的底层信念是什么

这份文档决定产品的“价值观”和“方法论”。

### `product-positioning.md`

这是产品定位文档。

主要回答：

- 产品做给谁
- 产品不是什么
- 产品真正是什么
- 它和其他工具的区别是什么

这份文档决定产品边界和对外表达方式。

### `../skills/README.md`

这是当前 AI/Skill 工作流总览。

主要回答：

- 当前有哪些 Skill
- 这些 Skill 的触发条件是什么
- 它们之间如何路由
- Agent 应该怎样使用 HiveFlow CLI

如果你想快速理解“AI 层现在放在哪里”，这份文档最直接。

### `mvp-requirements.md`

这是 MVP 文档。

主要回答：

- 第一版到底做什么
- 第一版不做什么
- 第一版先打哪些地基
- MVP 的成功标准是什么

这份文档决定第一阶段的范围。

### `product-design-plan.md`

这是设计与结构文档。

主要回答：

- 系统里的核心对象有哪些
- 模块之间怎么组织
- 主流程怎么跑
- 后续如何从地基走向更完整的系统

这份文档偏结构和方案，不再重复产品理念。

### `strategy-taxonomy.md`

这是策略分类文档。

主要回答：

- 第一版有哪些主要策略类型
- 不同策略分别适合哪个策略席位
- 第一版优先纳入哪些策略类别

这份文档负责把“策略池”和“策略席位”之间的关系写清楚。

## 当前写作原则

当前这批文档优先解决：

- 方向是否清楚
- 产品边界是否稳定
- MVP 是否收敛

当前暂时不优先展开：

- 界面设计
- 视觉稿
- 交互细节
- 前端形态选择

先把“我们到底要做什么”写清楚，再谈怎么呈现。
