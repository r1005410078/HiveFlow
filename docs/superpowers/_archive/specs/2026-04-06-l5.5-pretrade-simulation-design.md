# L5.5 预交易模拟设计

## Goal

实现 L5.5 预交易模拟层：基于 L4 组合优化权重，估算每笔订单的市场冲击成本（平方根模型）与可成交性，给出 per-symbol 冲击 bp 和整体 `overall_tradable` 评级。结果透传至 `run_daily` 的 `data.pretrade` 字段，并提供独立 HTTP 端点和 CLI 命令供日常巡检。

L5.5 是纯估算层：不阻断 pipeline（L5 已承担硬阻断职责），只产出信息供运营决策和 L6 执行参考。

## Architecture

```
CLI: hf pretrade check --as-of DATE --output json|table
  └─ POST /v1/pretrade/check  { as_of, target_weights, notional? }
       └─ get_pretrade_service() [dependencies.py]
            └─ run_pretrade_check(as_of, target_weights, bar_store, notional)
                 ├─ 取近 20 交易日 ADV（bar_store.list_bars, 1d, volume）
                 ├─ 取近 20 交易日波动率 σ（日收益率标准差 × sqrt(252)）
                 ├─ per-symbol: impact_bp = η × σ × sqrt(notional × w / ADV) × 10000
                 ├─ per-symbol: tradable = (notional × w / ADV) ≤ 0.10
                 └─ 汇总: total_impact_bp（权重加权均值）、overall_tradable

run_daily（daily_run_service.py）在 L5 之后插入 L5.5：
  risk_gate_result → pretrade_result → execution_plan（data.pretrade 字段）

  若 portfolio=None（L4 失败），L5.5 与 L5 一样跳过，`data.pretrade=null`。
```

CLI 两跳（与 `hf risk check` 完全对称）：
1. `POST /api/v1/portfolio/optimize` → 取 `target_weights`
2. `POST /v1/pretrade/check` → 传入 weights + notional（固定 1_000_000 CNY，Phase 1）

## Output Schema

HTTP 响应遵循标准 CLI 输出信封，`data` 字段定义如下：

```json
{
  "as_of": "2026-04-01",
  "notional": 1000000.0,
  "overall_tradable": true,
  "total_impact_bp": 8.3,
  "orders": [
    {
      "symbol": "600519.SH",
      "target_weight": 0.12,
      "target_notional": 120000.0,
      "adv": 850000000.0,
      "participation_rate": 0.000141,
      "sigma": 0.18,
      "impact_bp": 2.1,
      "tradable": true
    }
  ]
}
```

**字段说明：**

- `notional`：总资金（Phase 1 固定 1_000_000 CNY）
- `participation_rate`：`target_notional / ADV`
- `tradable`：`participation_rate ≤ 0.10`（默认阈值，不可配置，Phase 1）
- `impact_bp`：`η × σ × sqrt(participation_rate) × 10000`，η = 0.1（固定，Phase 1）
- `sigma`：近 20 交易日日收益率标准差 × sqrt(252)，最小值钳制为 0.01
- `adv`：近 20 交易日日均成交额（CNY），= mean(close × volume)
- `total_impact_bp`：各 symbol 按 `target_weight` 加权平均 impact_bp
- `overall_tradable`：所有 symbol `tradable=true` 才为 true

**bar_store 不可用时的降级行为：**

若 `bar_store=None` 或查询返回空行，ADV 降级为 1_000_000_000 CNY，σ 降级为 0.20，结果仍正常产出，但顶层 `warnings` 中追加：

```json
{"code": "PRETRADE_USING_FALLBACK_ADV", "message": "bar_store unavailable; using fallback ADV=1e9 and sigma=0.20"}
```

## Testing Strategy

### 单元测试 `test_pretrade_service.py`（mock bar_store）

1. 全部 symbol tradable → `overall_tradable=true`，`total_impact_bp` 合理正值
2. 一个 symbol `participation_rate > 0.10` → `tradable=false`，`overall_tradable=false`
3. `bar_store=None` → 降级 ADV，warning `PRETRADE_USING_FALLBACK_ADV`
4. bar_store 返回空行 → 同降级路径
5. σ 极小（< 0.01）→ 钳制为 0.01，impact 非零

### 合约测试 `test_http_pretrade.py`

1. `POST /v1/pretrade/check` 合法 payload → 200，schema 含所有必填字段
2. 缺少 `target_weights` → 422
3. `bar_store=None`（DB 不可用）→ 200，降级结果 + warning

### Rust CLI 测试

mock HTTP server 返回标准信封，验证：
- table 输出含 `overall_tradable` 行
- json 输出完整透传响应
- 两跳失败（L4 不可达）→ 输出 error 信封，exit code 非 0

## Impact Cost Model

```
impact_bp = η × σ × sqrt(participation_rate) × 10000

参数（Phase 1 均为固定值）：
  η = 0.1            # 市场冲击系数
  σ = realized_vol   # 近 20 交易日年化波动率，最小值 0.01
  participation_rate = target_notional / ADV
  ADV = mean(close × volume)，近 20 交易日
```

Phase 2 可引入：按市场状态（regime）动态调整 η；引入 bid-ask spread 估算。

## Future Work (Phase 2)

- η 动态化：regime=warning 时 η × 1.5，regime=crisis 时 η × 2.0
- bid-ask spread 估算：基于日内高低价差
- 历史冲击成本回溯：与实际成交价比对，校准 η
- `notional` 参数化：CLI 支持 `--notional` 参数
