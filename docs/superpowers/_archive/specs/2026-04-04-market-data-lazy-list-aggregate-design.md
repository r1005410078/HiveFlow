# 设计：行情列表懒加载 + bars 业务层聚合与游标分页

**日期**：2026-04-04  
**状态**：已与客户口头确认设计要点；**§5.2 已与「与主流 A 股行情终端周期一致」目标对齐**；实现前须再书面过一遍本文并批准 `implementation-plan`。  
**关联**：CLI `hf tui`、Python `GET /v1/market-data/bars`、L1 存储与同步。

---

## 1. 背景与问题

- 当前客户端（尤其 TUI）易在进入界面前 **一次性按整池批量请求 bars**，体积与延迟差。
- 当前 `GET /v1/market-data/bars` 用查询参数 **`timeframe` 直接筛库内 `bars.timeframe` 列**，等价于「同步/入库粒度」；**展示粒度与存储粒度被绑死**，无法在业务层从细粒度（如 1m）聚合出日/月/年 K 线。
- 表格场景需要 **按页向服务端拉取**，而非一次拉全量再在本地分页。

---

## 2. 目标

1. **服务端单独提供「标的列表」接口**，返回 **代码、中文名称等元数据**；客户端进入 TUI 时 **先拉列表，不依赖全量 bars** 拼左侧列表。
2. **选中标的后再请求 bars**；**表格模式**使用 **游标分页** 持续拉取。
3. **K 线 / 分时展示** 的周期与主流 **A 股行情软件（如东方财富、同花顺等终端的「分时 / 5 分·15 分·30 分·60 分 / 日 / 周 / 月 / 年」）语义一致**（**§5.2 为门禁**）；**与同步入库粒度解耦**；库内 **尽量存最细可用粒度**（当前最细为 **1m**；更细后续再扩展）。
4. **聚合仅在 application 业务层**（或业务层编排 + domain 规则），**不在 HTTP 路由内写算法**；adapter 可负责 **按存储粒度读原始行**，聚合逻辑归属 application/domain。

---

## 3. 非目标（本期不做）

- 秒/毫秒级入库与聚合（仅预留扩展点）。
- 替换现有异步 `sync` 任务模型；本文只读 **查询与列表** 路径。
- GraphQL 或单一 POST 查询体（保持 REST + GET 为主，与现有 CLI 一致）。

## 5. 架构与分层（Python）

- **`interfaces/http`**：路由只做 DTO 解析、调用 application service、返回响应 DTO；**不写聚合算法**。
- **`application/market_data`**（或等价用例模块）：编排 **instruments 列表**、**bars 查询（读细粒度 → 聚合 → 分页切片）**。
- **`domain`**：桶边界、OHLC 合并规则、时区约定（与现有 **Asia/Shanghai** 存储一致）等 **纯规则**，无 HTTP/DB 框架依赖。
- **`interfaces/adapters`**：`TimescaleBarStore`（或专用读端口）提供 **按存储粒度、时间窗、标的读原始行** 的能力；是否下推 `time_bucket` 由实现计划权衡，但 **聚合语义须在 application/domain 可单测**。

### 5.1 聚合算法（输出桶 OHLC，与 CLI `domain::bars_aggregate` 语义对齐）

**输入**：某 `symbol` 在查询时间窗内、按 **存储粒度**（如 `1m`）读出的有序序列（按 **`bar_time` 升序**）。  
**输出**：按请求的 **`timeframe`（输出桶宽）** 分桶后，每桶一根合成 K 线。

#### 单桶内 OHLC（与业界常规定义一致）

| 字段 | 规则 |
|------|------|
| **open** | 桶内 **第一根**（时间最早）细 K 的 `open` |
| **high** | 桶内所有细 K 的 `high` 的 **max** |
| **low** | 桶内所有细 K 的 `low` 的 **min** |
| **close** | 桶内 **最后一根**（时间最晚）细 K 的 `close` |
| **volume / amount**（若存在） | 桶内 **求和**；`null` 与 0 的合并规则在实现计划中写死（建议：null 当 0 参与求和，或全 null 则输出 null） |

**空桶**：不产生输出行（不填充 0 价假 K）。

#### 时区

- 所有 **桶界**、日期归属均以 **`Asia/Shanghai`** 解释 `bar_time` 的「日历日期」（与当前 `bars.bar_time` timestamptz 存储一致）。
- **`1w` / `1M` / `1y` 的分桶边界与 `bar_time` 锚点** 以 **§5.2（终端对齐）** 为准；§5.1 下表中的 **`1M`/`1y` 锚点若与 §5.2 冲突，以 §5.2 为准**（月线/年线采用 **先合成日 K 再二次聚合**，与同花顺/东财类 **月K/年K** 常见算法一致，而非直接从分钟跨月硬聚一根）。

#### 输出 `bar_time`（桶锚点）

- 每一根合成 K 的 **`bar_time`** 为该桶的 **规范锚点时刻**（ISO-8601 + 偏移），便于客户端与游标对齐；**同一 `timeframe` 全仓统一一种锚点规则**。

#### 交易日历（仅用于 `1d`）

- **`1d` 桶 = A 股「交易日」**，以上交所 **SSE** 开市日历为准（与常见 A 股日线惯例一致）：**周六日、法定节假日等休市日不产生日 K 桶**。
- **实现**：在 **`domain`**（或纯函数模块）提供「某日是否 SSE 交易日」「区间内交易日枚举」等能力；**具体数据源**（如 `exchange_calendars`、akshare 交易日接口、或维护静态节假日表）在 **implementation-plan** 选定，须 **可单元测试**、**HTTP 路由内不写日历算法**。

#### 细 K 归入哪一个交易日（`1d`）

- 将每根存储粒度 K 线的 `bar_time` 转为 **`Asia/Shanghai` 的日历日期 `D`**。
- 若 **`D` 是 SSE 交易日**，该细 K 归入 **交易日 `D`** 对应的那一根日 K 桶。
- A 股常规交易不跨自然日；若未来存在跨日品种，**另开 spec** 约定会话切分。

#### 各 `timeframe` 桶定义（本期）

| 请求 `timeframe` | 桶含义 | 桶锚点 `bar_time`（规范） |
|------------------|--------|---------------------------|
| **`1m`** | 与存储 1m 一致时 **可直接透传** 细行；若上游存在更细（未来）再聚到整分 | 该分钟 **起始** `+08:00`（与库内对齐） |
| **`1d`** | **SSE 交易日**：该交易日内全部用于聚合的细 K（如当日全部 `1m`）合并为一根日 K | **`T` 日 `15:00:00+08:00`**（与现有 `AkshareQuoteAdapter` 日线 `bar_time` 及常见「收盘锚点」一致，便于与已入库 `1d` 行对齐） |
| **`1M`** | **见 §5.2**：公历月内 **先按 §5.1 得到每一 SSE 交易日的 `1d`**，再对月内日 K **二次 OHLC 合并** | **§5.2**：**该公历月内最后一个 SSE 交易日的 `15:00:00+08:00`** |
| **`1y`** | **见 §5.2**：公历年内 **先得到全年各交易日 `1d`**，再对年内日 K **二次 OHLC 合并** | **§5.2**：**该公历年内最后一个 SSE 交易日的 `15:00:00+08:00`** |
| **`1w`** | **见 §5.2**：ISO 周内日 K 二次合并 | **§5.2**：**该 ISO 周内最后一个 SSE 交易日的 `15:00:00+08:00`** |
| **`5m` / `15m` / `30m` / `60m`** | **见 §5.2**：**交易时段内**自 **9:30** 起按固定步长分桶，由存储 **`1m`** 聚合 | 各桶 **时段结束时刻**（见 §5.2） |

**注**：`timeframe=1m` 在请求带 **`session_date`** 时表示 **分时**（§5.2.1–5.2.2），**仅返回该交易日、时段裁剪后、按时间升序**；不带 `session_date` 时为 **历史分钟 K**，默认 **`bar_time desc`** 分页（§6.2）。

#### 客户端切换为「天」（`timeframe=1d`）时：服务端返回几个点？每个点怎么算？

**返回点数（逻辑条数，再受 `limit` / 游标分页截断）**

- 设查询日期窗为 `[start_date, end_date]`（与 API 文档中的 **闭区间** 定义一致；若与现网不一致，实现时在 plan 中统一并改契约测试）。
- 令 **`N_max`** = 该窗口内 **SSE 交易日** 的个数。
- 服务端 **潜在可输出的日 K 根数** = 满足以下条件的交易日 **`T` 的个数**：
  - `T` 落在 `[start_date, end_date]` 内；且  
  - **`T` 当日至少存在 1 根** 参与聚合的存储粒度 K 线（默认 **`1m`**）。  
- 因此：**`点数 ≤ N_max`**；**缺分钟数据的交易日不出现在结果里**（**不补空日、不填零价假 K**）。
- **HTTP 响应一页**：在聚合后的序列上按 **`bar_time desc`** 排序，再取前 **`limit`** 条（并配合 **`cursor_*`** 翻页），故 **单次响应条数 `≤ limit`**，总逻辑点数仍由上式决定。

**每一个日 K「点」的计算步骤**

1. **分桶**：取出查询时间窗内、该 `symbol` 下所有存储粒度（如 `1m`）的细 K，按 §「细 K 归入哪一个交易日」归入各交易日 `T`。
2. **过滤**：丢弃 **非交易日** 日期上的细 K；丢弃 **窗口外** 的细 K。
3. **每桶一根**：对每个 **有至少一根细 K** 的交易日 `T`，将该日桶内细 K 按 **`bar_time` 升序** 排列，按上文 **「单桶内 OHLC」** 表合并为 **一根** 合成 K 线（open=当日第一根分钟 open，…，close=当日最后一根分钟 close，volume 等求和）。
4. **写出字段**：`timeframe` 字段为 **`1d`**；`bar_time` = **`T` 日 `15:00:00+08:00`**。

**与「同步粒度」的关系**：即使库里同时存在直接同步写入的 `1d` 行，**本查询路径仍以「读细粒度 → 业务层聚合成请求 `timeframe`」为准**（你已选统一语义）；聚合结果的时间锚与现有 akshare 日线 **`15:00+08`** 对齐，减少混用时的认知分裂。

#### 部分桶（窗口截断）

- 查询 `start_date`/`end_date` 仅覆盖某个 **交易日 / 月 / 年** 桶的 **一段时间** 时：仍生成该桶，但 **只使用窗内的细 K** 做 OHLC。**不在窗外补全** 不存在的细数据。  
- **交易日 `T` 仅有一部分分钟落在窗口内**（例如 `start_date = end_date = T` 但只查午后）：仍输出 **一根** `1d` 桶，OHLC **仅由窗内分钟** 按上规则计算（可能不同于「全日」日 K）。

### 5.2 与主流 A 股行情终端周期对齐（门禁）

本节约定 **HiveFlow 对外语义** 与常见终端在 **A 股现货** 上的 **周期与锚点** 一致；**不承诺**与某一商业 App **像素级或未公开实现**逐字节一致，但 **桶界、排序方向、月/年是否经日 K 二次聚合、分时是否单日** 等须按本节 **可单测** 验收。若未来需对标 **指定产品** 的截图回归，在 `implementation-plan` 中增加 **golden fixture** 即可。

#### 5.2.1 名词：「分时」vs「历史分钟 K」

- **分时（intraday / 分时图）**：**仅一个 SSE 交易日** 的盘中序列；客户端通常画 **成交价曲线 + 成交量柱**（**不是**多日连起来的历史分钟 K 线）。**API 侧** 以 **`timeframe=1m` + 单日 `session_date`（或 `start_date=end_date=session_date`）** 表达；**排序为 `bar_time asc`**（从早到晚），与默认列表游标 **`desc`** 区分。
- **历史分钟 K（`1m`）**：可跨多自然日；**默认 `bar_time desc` + 游标分页**（§6.2）。TUI/图表若从左到右展示，客户端对 **一页或一段** 本地 `reverse` 即可。

#### 5.2.2 分时数据范围（与常见终端横轴一致）

- **`session_date`（YYYY-MM-DD）** 必须为 **SSE 交易日**；否则 **422**（明确 `code`）或 **空 `items`**（二选一整仓一致，推荐 **422**）。
- **纳入聚合的存储粒度行**：仅 **`bar_time` 落在该自然日（上海日历）且落在下列时段内** 的 **`1m`** 行（左闭右开区间）：
  - **连续竞价上午**：`09:30:00`–`11:30:00`（+08）
  - **连续竞价下午**：`13:00:00`–`15:00:00`（+08）
- **集合竞价（如 9:15–9:25、14:57–15:00 等）**：若 **库内已有** 对应分钟线，**保留在结果中**（位置按时间升序）；若数据源 **未提供** 竞价分钟，则 **不造零价假 K**。验收时以 **当前入库的 akshare/适配器行为** 为基线，并在计划中列 **与东财/同花顺是否同屏可见** 的抽样说明即可。
- **非交易日、非上述时段** 的分钟行：**不得**出现在「分时」响应中。

#### 5.2.3 多周期分钟 K（`5m` / `15m` / `30m` / `60m`）

在 **每一个 SSE 交易日** 内，仅对 **§5.2.2 同一时间基上的 `1m` 子集**（可与分时同口径，含数据源已提供的竞价分钟）做分桶：

- **步长**：`5`、`15`、`30`、`60` 分钟。
- **上午段**：自 **`09:30:00+08`** 起，连续 **`[t, t + Δ)`** 左闭右开，直至 **`11:30:00`**（最后一根若不足整步长，**仍成一桶**，OHLC 仅由桶内已有分钟合并，**不补全**）。
- **下午段**：自 **`13:00:00+08`** 起，同样规则直至 **`15:00:00`**。
- **午间休市**：**不产生**桶。
- **单桶 OHLC**：同 §5.1「单桶内 OHLC」。
- **桶锚点 `bar_time`**：**该桶右边界时刻**（即区间 **结束** 瞬时，`+08`），例如上午第一根 `5m` 为 **`09:35:00+08`**；便于与常见软件「该根 K 线对应时段终点」习惯对齐。若与某 App 采用「左边界锚点」不一致，以本节为准并在 UI 层做标签偏移（**API 锚点不变**）。

**跨日**：每个交易日独立分桶；历史查询返回多日时，**按 `bar_time` 全局升序或降序** 与 §6.2 统一（默认仍 **`desc` 分页** 时，以 **桶锚点** 参与排序）。

#### 5.2.4 周线 `1w`（先日再周）

- **周界**：**ISO 8601 周**（**周一 00:00:00** 至 **下周一 00:00:00**，上海时区，左闭右开）。
- **步骤**：
  1. 在查询时间窗内，按 §5.1 先得到每一 SSE 交易日的 **`1d`** 合成根（每根锚点为 **该日 `15:00+08`**）。
  2. 将各 **`1d` 根按其 `bar_time` 所属自然日** 映射到 ISO 周。
  3. 对每一周内的 **多根 `1d`** 再按 §5.1 **OHLC 合并** 为 **一根周 K**（open=周内 **按交易日顺序** 第一根日 K 的 open，close=最后一根日 K 的 close，high/low 为周内日 K high/low 的 max/min）。
- **周 K 的 `bar_time` 锚点**：**该 ISO 周内最后一个 SSE 交易日的 `15:00:00+08:00`**。若该周无交易日（极罕见），**不输出**。

#### 5.2.5 月线 `1M`、年线 `1y`（先日再月/年 — 与常见月K/年K一致）

- **月界 / 年界**：**上海时区公历月 / 公历年**（与 §5.1 原「左闭右开」一致）。
- **步骤**：
  1. 在查询时间窗内，先按 §5.1 得到每一交易日的 **`1d`**。
  2. 将各 **`1d` 按锚点所属公历月（或年）** 分组。
  3. 组内多根 **`1d`** 按 **交易日 `bar_time` 升序** 做 §5.1 OHLC 合并，得到 **一根月 K / 年 K**。
- **`bar_time` 锚点**：**该公历月（或年）内最后一个 SSE 交易日的 `15:00:00+08:00`**。  
  - *说明*：终端 UI 上「月 K 标签」有时显示为月末自然日，**数据锚点仍用最后交易日 15:00**，与 **日线收盘锚点体系** 一致，避免与已入库 `1d` 混用时漂移。

#### 5.2.6 季线 `1Q`（可选，若本期实现）

- **季界**：**公历季** Q1–Q4（上海时区，**季首月 1 日 00:00** 至 **下一季首月 1 日 00:00**，左闭右开）。
- **算法**：同 §5.2.5，**先 `1d` 再合并**；**锚点** = **该季内最后一个 SSE 交易日 `15:00+08`**。若本期不实现，`timeframe=1Q` 返回 **422**。

#### 5.2.7 验收

- **单元测试**：分时时段裁剪、5m 上午第一根锚点 `09:35+08`、月/年 **open 等于月内首个交易日日 open**（而非「自然月第一个有数据的分钟的 open」）、**周线 ISO 周界**。
- **可选**：对接 **东方财富/同花顺** 同一标的、同一交易日导出数据抽样比对（计划阶段定是否自动化）。

## 6. API 设计

### 6.1 `GET /v1/market-data/instruments`

**用途**：轻量标的列表，供 TUI/CLI 首屏与筛选。

**查询参数（建议）**：

- **`mode`**（必填）：`universe` | `db`。
- **`mode=universe`**：`universe` 必填（如 `csi300`）；解析规则与现有 universe 文件/服务侧约定一致。
- **`mode=db`**：
  - `start_date`、`end_date`（可选，YYYY-MM-DD）；**均未传时**：窗口为 **「今天起往回共 7 个自然日」**（与已确认默认 **N=7** 一致）。
  - **`min_bars`**（可选，默认 **1**，即已确认 **K=1**）。
  - **`storage_timeframe`**（可选，默认 **`1m`**）：判定「是否有数据」时只计该存储粒度的行。
- **列表分页**（建议与 bars 游标风格一致、明文）：`limit` + `cursor_symbol`（或 `after_symbol`，字典序 **`symbol asc`**）；响应带 `next_cursor_symbol` / `has_more`。具体字段名在实现计划中定稿并与 Rust 客户端对齐。

**响应**：`items: [{ symbol, symbol_name_zh, ... }]`；名称与现有 `symbol_names` / 中间件 enrich 策略对齐（无映射时空字符串）。

### 6.2 `GET /v1/market-data/bars`（语义变更）

**语义变更（破坏性）**：

- **`timeframe`**：**仅表示响应条的 K 线周期（输出桶宽）**，例如 `1m`、`5m`、`15m`、`30m`、`60m`、`1d`、`1w`、`1M`、`1y`（可选 `1Q`）；**桶界、锚点与 OHLC 见 §5.1 / §5.2**。
- 服务端 **从库内可用最细粒度**（默认 **`1m`**，未来可配置「每 symbol 最细可用档」）读取覆盖时间窗的原始行，在 **业务层聚合** 为请求的 `timeframe` 后返回。
- **不再**用 `timeframe` 直接等价于 `where bars.timeframe = %s` 的旧语义。

**查询参数**：

- `symbols`：建议 **首版 TUI 仅单标的**；若传多标的，**与 `cursor_*` 同时使用时**须在实现计划中 **禁止或定义每 symbol 独立游标**（推荐首版：**游标分页仅允许单 symbol**）。
- `start_date`、`end_date`：与现有一致（闭区间或按现有约定）。
- **`session_date`（可选，YYYY-MM-DD）**：与 **`timeframe=1m`** 联用表示 **分时（§5.2.1–5.2.2）**；此时 **`start_date`/`end_date` 应与之同义或省略**（实现计划在 DTO 层二选一成文）。**响应排序为 `bar_time asc`**；**不参与默认 `desc` 游标翻页语义**（分时通常一次性返回当日全部分钟，或 `limit` 极大；若仍分页，游标方向须在计划中写清为 **自早向晚**）。
- `timeframe`：输出桶宽（§5.1 表 + §5.2）。
- `limit`：本页条数上限（上限与现有一致或略调，计划中写清）。
- **游标（明文）**：`cursor_bar_time`（ISO-8601 字符串，与返回 `bar_time` 同精度）、**`cursor_symbol`**（多标的时必填；单标的可省略）。

**排序**：默认聚合后结果按 **`bar_time desc`**（与当前 `list_bars` 习惯一致）；**唯一例外**：**分时**（`session_date` + `1m`）为 **`bar_time asc`**（§5.2.1）。

**响应**：

- `items`：与现形相近（`symbol`, `timeframe`, `bar_time`, OHLC, …），其中 **`timeframe` 为输出桶宽**。
- **下一页**：`next_cursor_bar_time` / `next_cursor_symbol`（或嵌套对象）；无更多则为 `null`。

**错误与边界**：

- 请求的 **`timeframe` 比存储最细更细**（如要 `1s` 仅有 `1m`）：**422** + 明确 `code`（实现计划列枚举）。
- 窗内无可聚合的细粒度数据：**空 `items`**（或统一用 **422**，二选一整仓一致；**推荐空列表 + 可选 `warnings`**，便于 TUI 展示）。
