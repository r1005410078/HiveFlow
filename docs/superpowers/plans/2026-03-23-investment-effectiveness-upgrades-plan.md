# 2026-03-23 规划：提升真实投资有效性的 8 项改造

## 1. 背景

当前 HiveFlow 已经具备：

- 真实状态层（持仓、行情、信号、回测、绩效）
- 确定性工具层（CLI、JSON、调仓预览、执行）
- Skill 工作流层与外部 Agent Runtime

但如果目标是“更有利于长期真实投资”，系统还缺少一组更接近主流量化实务的能力：

- 更实盘化的策略评价
- 更稳定的策略切换规则
- 更严格的执行门槛
- 更明确的组合级风险约束

## 2. 目标

在不破坏“系统只输出确定性数据与规则，Skill 负责流程，外部 Agent Runtime 负责执行与交互”边界的前提下，补齐最能提升真实投资体验的 8 项能力。

## 3. 非目标

- 不建设高频交易系统
- 不引入 LLM 直接下单决策
- 不优先扩张到大而全市场覆盖
- 不做复杂强化学习交易框架

## 4. 架构原则

本轮改造不推翻现有三层架构：

1. `HiveFlow`
2. `Skill`

`Agent Runtime` 属于项目外部执行环境，不在本轮内部架构改造范围内。

但要求在 HiveFlow 内部进一步分层：

1. `State Layer`
- 持仓、行情、信号、回测、绩效、日志

2. `Evaluation Layer`
- 回测实盘化指标、参数稳定性、策略健康度

3. `Policy Layer`
- 策略切换规则、组合约束、执行门槛

4. `Execution Layer`
- 偏离检测、调仓预览、订单生成、交易执行

## 5. 八项改造清单

### 5.1 调仓执行门槛

目标：
- 降低噪音交易与过度操作

建议能力：
- 最小偏离阈值
- 最小交易金额
- 冷却期
- 单次最大换手
- 高风险时禁止加仓

分层落位：
- HiveFlow `Policy Layer`

优先级：
- P0

### 5.2 策略切换规则层

目标：
- 把“什么时候该切换策略”从临场解释，提升为稳定规则

建议能力：
- 市场状态到策略类型的映射
- 切换阈值
- 不切换条件
- 防守模式触发条件

分层落位：
- HiveFlow `Policy Layer`
- Skill 只负责解释与交互

优先级：
- P0

### 5.3 回测实盘化指标

目标：
- 避免只看纸面收益，提升策略评价的真实度

建议能力：
- 换手率
- 手续费影响
- 滑点影响
- 连续亏损期
- 分市场阶段表现

分层落位：
- HiveFlow `Evaluation Layer`

优先级：
- P0

### 5.4 组合级风险约束

目标：
- 把组合安全边界前置，而不是等到风险爆发后再解释

建议能力：
- 单资产权重上限
- 高相关资产总暴露上限
- 现金 / 防守仓位下限
- 风险抬升时自动降暴露

分层落位：
- HiveFlow `Policy Layer`

优先级：
- P0

### 5.5 策略健康度监控

目标：
- 识别策略失效、退化和暂停条件

建议能力：
- 最近 N 窗口表现退化检测
- 是否持续跑输基准
- 健康度标签：`healthy / degrading / paused`

分层落位：
- HiveFlow `Evaluation Layer`

优先级：
- P1

### 5.6 参数稳定性检验

目标：
- 降低过拟合风险，提升策略可信度

建议能力：
- 参数网格结果
- 邻域稳定性
- Walk-forward / 分段验证

分层落位：
- HiveFlow `Evaluation Layer`

优先级：
- P1

### 5.7 决策复盘记录

目标：
- 让系统能回答“为什么当时这么做，后来结果如何”

建议能力：
- 记录当时上下文
- 记录策略选择
- 记录预期与结果
- 记录是否偏离计划

分层落位：
- HiveFlow `State Layer`
- Skill 负责解释复盘

优先级：
- P1

### 5.8 统一策略选择契约

目标：
- 让 Skill 与 Agent 在“选策略”上有稳定输入输出结构

建议能力：
- `market_regime`
- `risk_budget`
- `strategy_health`
- `switch_recommendation`
- `switch_reason`

分层落位：
- HiveFlow `Evaluation Layer` + `Policy Layer`

优先级：
- P1

## 6. 推荐实施顺序

### Phase A：先做最直接影响收益体验的能力

1. 调仓执行门槛
2. 策略切换规则层
3. 回测实盘化指标
4. 组合级风险约束

说明：
- 这 4 项对真实投资帮助最大
- 可以先不动 Skill 结构，只增强 HiveFlow 输出

### Phase B：再做稳定性与长期监控

5. 策略健康度监控
6. 参数稳定性检验
7. 决策复盘记录
8. 统一策略选择契约

说明：
- 这 4 项对长期演进、可复盘和 Skill 稳定性帮助更大

## 7. 对 Skill / Agent 的影响

这些改造完成后，Skill 的职责会更清晰：

- `daily-check`：更依赖组合约束和执行门槛输出
- `strategy-selector`：更依赖策略健康度、阶段表现、切换规则
- `rebalance-executor`：更依赖执行门槛与组合约束

结论：
- Skill 负责“解释、路由、交互”
- HiveFlow 负责“规则、评价、约束、动作接口”

## 8. 风险与注意事项

### 风险 1：规则散落到 Skill 中

缓解：
- 任何确定性规则优先下沉到 HiveFlow

### 风险 2：回测增强过重，拖慢迭代

缓解：
- 先做指标增强，再考虑更复杂的 Walk-forward 自动化

### 风险 3：策略切换过于频繁

缓解：
- 同时引入切换阈值与冷却期

## 9. 验收标准

完成后至少应满足：

1. `backtest` 输出比现在更接近实盘决策需要，而不只是收益摘要
2. `strategy-selector` 不再只依赖临场解释，能读取明确的结构化切换依据
3. `rebalance preview` 不再对所有偏离都一视同仁，而受执行门槛与组合约束控制
4. 系统能够输出“策略当前是否健康”和“当前是否值得切换”

## 10. 一句话总结

这 8 项改造的核心，不是让 HiveFlow 变成更重的量化平台，而是让它从“能分析、能回测、能调仓”升级为“更适合长期真实投资使用”的系统。
