# HiveFlow 系统架构设计 v2（实盘导向）

> 本文档定义量化系统的目标架构、层间契约与上线闸门。
> 目标是：可复现、可审计、可回滚、可实盘。
> 文档导航：`DOCUMENTATION_INDEX.md`
> 文档目标：定义量化系统整体架构与治理边界。适用对象：架构设计、策略研发、平台工程。

---

## 1. 架构总览

当前运行形态：

- `quant` 是部署到服务器上的 Python HTTP 服务端。
- `cli` 是安装在本机的 Rust 客户端，通过 HTTP 调用 `quant`。
- 本地不再通过 `python -m hiveflow.cli ...` 直接驱动量化主流程。

```text
外部数据源（行情/财报/公告/新闻/交易所元数据）
  ↓
L0 标的池层（Universe）
  ↓
L1 数据层（采集/清洗/存储）
  ↓
L2 因子层（原始特征）
  ↓
L3 信号工程层（稳健化+中性化+标准化+聚合）
  ↓
L4 组合优化层（目标函数+约束+成本）
  ↓
L5 风险门控层（Regime-aware 硬约束）
  ↓
L5.5 预交易模拟层（可成交性/冲击成本）
  ↓
L6 执行层（订单状态机+熔断+降级）
  ↓
L8 监控复盘层（归因诊断+反馈闭环）

── 横切层 ──────────────────────────────────────
G1 数据治理层（PIT/版本/审计）       贯穿 L0~L8
G2 实验治理层（实验注册/参数版本/结果追踪）
G3 执行安全层（应急接管/权限/操作审计）
L7 回测/验证层（贯穿 L0~L6）
```

---

## 2. 设计原则

1. **先可复现，再追收益**：任何结果必须能用同版本数据和代码复算。
2. **先安全，再自动化**：执行自动化以风险闸门为前提。
3. **先契约，再扩展**：层间输入输出先定义 schema，再实现。
4. **先验证，再上线**：无验证报告的策略/参数不能进实盘。
5. **先观测，再调参**：没有诊断证据，不做拍脑袋优化。

## 3. 各层职责

### L0 标的池层（Universe）

- 功能：定义“可交易集合”，过滤不可交易、低流动性、高异常资产。
- 规则：
  - 流动性阈值（成交额/成交笔数）
  - 上市时长阈值
  - 特殊状态过滤（停牌/ST/退市风险）
  - 交易制度过滤（最小单位/涨跌停限制）
- 输出：`universe_snapshot(as_of, symbols, reason_codes, version)`。

### L1 数据层

- 功能：采集、清洗、对齐、落库。
- 处理：
  - 时区统一
  - 复权口径明确
  - 发布延迟处理（财报/公告）
  - 异常与缺失策略（明示，不隐式填充未来数据）
- 输出：标准化宽表/长表 + 质量指标。

### L2 因子层

- 功能：从 L1 生成原始因子值（不做合并决策）。
- 规范：
  - 因子定义、窗口、方向、单位固定
  - 每个因子独立版本号
  - 因子可用率与稳定性监控
- 输出：`factor_matrix(as_of, symbol, factor_name, raw_value, factor_version)`。

### L3 信号工程层

- 功能：把因子转换为可比较、可聚合的信号。
- 标准流程：
  1. 去极值（winsorize/robust clipping）
  2. 缺失处理（行业中位/分组回填/剔除）
  3. 中性化（对去极值/缺失处理后的因子做行业/市值/风格暴露回归，取残差）
  4. 标准化（对中性化残差做 zscore/robust zscore）
  5. 稳健聚合（加权或分层聚合）
- 输出：`signal_matrix` + 诊断指标（覆盖率、漂移、IC、稳定性）。

### L4 组合优化层

- 功能：从信号到目标权重。
- 目标函数（示例）：
  - `max(alpha - risk_penalty - cost_penalty - turnover_penalty)`
- 约束（示例）：
  - 单标的上限、行业上限、杠杆上限
  - 容量约束（成交量占比）
  - 换手约束
  - 现金与最小交易单位约束
- Fallback（求解失败时）：优先维持上期权重；若无上期记录则对当前 universe 等权分配；极端情况（约束不可行）则全仓现金并记录原因。Fallback 路径必须落审计日志。
- 输出：`target_weights` + `optimization_report`（含求解状态与 fallback 标记）。

### L5 风险门控层

- 功能：执行前硬拦截，不参与收益博弈。
- 机制：
  - 市场状态机：`normal/warning/crisis`
  - 动态阈值：随状态切换
  - 组合级与单资产级双层规则
- 输出：
  - `pass` -> L5.5
  - `block` -> 拒单码 + 证据快照 -> L8（审计日志）

### L5.5 预交易模拟层

- 功能：检查“理论可行”是否“交易可行”。
- 模拟：
  - 可成交性（盘口深度/成交量）
  - 冲击成本与滑点估计
  - 部分成交与剩余订单处理策略
- 输出：
  - `pass` -> `execution_plan_candidate`（含预估成本区间）-> L6
  - `block` -> 拒单码（如 `LIQUIDITY_INSUFFICIENT` / `IMPACT_COST_EXCEEDED`）+ 原因记录 -> 反馈 L4（触发换手约束收紧）和 L8（审计）
- 反馈触发门槛：同类 `block` 在滚动 5 个交易日内出现 >= 3 次，才触发 L4 参数收紧。

### L6 执行层

- 功能：把执行计划转换为真实订单并跟踪生命周期。
- 必备：
  - 订单状态机（new/partially_filled/filled/canceled/rejected）
  - 幂等提交（避免重复下单）
  - 失败重试与上限
  - 熔断与降级（如只减仓、暂停新开仓）
  - 人工接管入口（仅异常路径）
- 输出：成交回报、滑点、延迟、异常码。

### L7 回测/验证层（贯穿）

- 功能：验证 L0~L6 的真实可行性（含标的池规则有效性与幸存者偏差检查）。
- 必须覆盖：
  - 无前视时间推进
  - 手续费+滑点+流动性+容量约束
  - 停牌/退市/最小交易单位处理
  - Walk-forward 或滚动窗口验证
- 输出：验证报告、压力测试结果、上线建议（Go/No-Go）。

### L8 监控复盘层

- 功能：运行监控、收益归因、偏差诊断、反馈闭环。
- 输出：
  - 实盘 vs 回测偏差分解（信号/优化/执行）
  - 因子健康度变化与失效预警
  - 风控触发统计与误报率
  - 策略变更建议（需经 G3 审批流）

### G1 数据治理层（横切）

- 功能：保证无前视、可审计、可重放。
- 覆盖范围：L0~L8 全链路（研究、交易、复盘统一可追溯）。
- 必备能力：
  - `Point-in-time` 数据快照
  - 数据版本哈希（dataset_id）
  - 字段血缘与来源记录
  - 数据质量报告（缺失率、异常率、延迟）
- 输出：`data_manifest`（用于回测/实盘统一引用）。

### G2 实验治理层（横切）

- 记录：实验假设、参数、代码版本、数据版本、结果摘要。
- 要求：每次参数变更必须可追溯到实验记录。

### G3 执行安全层（横切）

- 管控：权限分级、变更审批、紧急停机、一键回滚、操作审计。
- 要求：关键动作（上线/阈值改动）必须双人复核或审批流。

## 4. 层间契约（最小必备）

所有层间契约必须包含 `schema_version`、`generated_at`、`producer_version`，并遵循“向后兼容优先”；破坏性变更必须升级主版本并保留至少一个版本窗口。

1. `L0->L1 标的池契约`：universe_snapshot 字段（as_of、symbols、reason_codes、version），L1/L2 必须在同一 as_of 下引用，不得使用未收录标的。
2. `L1->L2 数据契约`：字段、时区、复权口径、发布时间、生效时间、dataset_id（来自 G1）。
3. `L2->L3 因子契约`：因子名、方向、窗口、缺失策略、factor_version。
4. `L3->L4 信号契约`：信号值域、置信度、覆盖率、漂移指标。
5. `L4->L5 组合契约`：目标函数、约束、求解状态、fallback 标记。
6. `L5 与 L5.5 均 pass 后进入 L6 执行契约`：订单模板、成本预估、拒单码。
7. `L6->L8 复盘契约`：成交明细、滑点、失败原因、时延。

## 5. 反馈闭环（自动化触发）

- L8 -> L2/L3：因子衰减触发重检或退役评估。
- L8 -> L4：执行成本抬升触发换手惩罚重标定。
- L8 -> L5：误报率或漏报率异常触发阈值回测重标定（误报率高 → 阈值过严；漏报率高 → 阈值过松）。
- L5 -> L4：组合级 block 累积达门槛，触发 L4 约束收紧（如降低单资产上限或行业集中度上限）。参考门槛：滚动 5 个交易日内组合级 block >= 3 次。
- L5.5 -> L4：流动性/冲击成本 block 累积达门槛，触发换手约束收紧（门槛定义见 L5.5 职责）。
- L7 -> 全链路：上线门槛不达标则阻断该策略/参数变更发布到实盘。

## 6. 上线闸门（Go/No-Go）

满足以下条件才可上线。括号内为参考示例值，**需按策略类型和目标市场单独校准，不可跨策略套用**：

1. 回测覆盖完整市场周期（至少含 1 次高波动区间）。
2. Walk-forward 表现稳定，非单一区间有效。
3. 成本后收益仍满足门槛（参考：净年化收益 >= 6%，成本侵蚀率 <= 30%）。
4. 风险指标（MDD/波动/尾部风险）在预算内（参考：MDD <= 20%，年化波动 <= 25%）。
5. 执行仿真通过（参考：拒单率 <= 2%，滑点 P95 <= 30bp，端到端延迟 P95 <= 2s）。
6. 变更记录完整（数据版本、代码版本、参数版本可追溯）。

## 7. 因子生命周期治理（防 Factor Zoo）

- 准入：有效性、稳定性、独立性三项同时达标。
- 观察：按周/月追踪贡献、IC、漂移、覆盖率。
- 降权：性能衰减先降权观察，不直接删除。
- 退役（失效）：持续失效且统计显著时退役。
- 退役（冗余）：与现有活跃因子相关性持续 > 0.8 → 退役 IC 更低或更不稳定的那个，保留另一个。
- 复活：新样本复验通过后可重新激活。

## 8. AI 在系统中的位置

- AI 参与：研究假设生成、回测解读、复盘诊断、规则建议。
- AI 不参与：数据落地、风控硬拦截、实时下单决策。
- 原则：**AI 辅助设计，规则驱动执行**。
- 落地细则：参见 `AI_SKILLS_INTEGRATION.md`（Skills + CLI 解耦方案）。

## 8.1 客户端与服务端边界

- `quant` 通过 HTTP 暴露量化编排能力，MVP 主接口为 `POST /api/v1/pipeline/daily`。
- `cli` 负责命令解析、配置加载、错误码映射和 HTTP 请求发送。
- `cli` 默认从 `~/.hiveflow/config.toml` 读取服务端地址和超时配置。

最小配置示例：

```toml
server_url = "http://127.0.0.1:8000"
timeout_ms = 10000
retry = 1
```

## 8.2 Quick Start / Runtime Prerequisites

当前 CLI 数据查询形态（与运行实现对齐）：

- `hf task list --output`（别名 `hf task sync-runs`）仅支持 `json|table`，用于同步任务列表（`/v1/market-data/sync-runs`）；`hf task progress`（别名 `hf task status`）查看运行中进度（默认识别唯一 `running` 或 `--run-id`；`--watch` 轮询至终态，对应 `GET /v1/market-data/sync-runs/{run_id}`）；取消与补拉失败对应 **`hf task cancel` / `hf task retry-failed`**（亦保留 `hf data sync-cancel` 等别名）。近窗 K 线用 `hf data query`（`GET /v1/market-data/bars`，`json|tui|table`，默认 TUI 分页）；显式区间/chart 用 `hf data bars`。列表/详情中的 **`effective_symbols_count`** 与 **`progress.total_symbols`** 在实现上应对齐（finalize + 读取 enrich）；同步无行返回时可为 **`success` + `NO_DATA_RETURNED`**。
- `hf data bars --output` 支持 `json|table|chart|tui`，用于查询 K 线明细（`/v1/market-data/bars`）。
- `data bars` 的 `chart` 模式要求单标的 `--symbols`（如 `600519.SH`）。
- `data bars` 的 `tui` 模式支持左侧选股与键盘交互（`↑/↓` 切换、`←/→` 光标、`a/d` 平移、`+/-` 缩放、`0` 重置、`b` 开关大盘对比）。
- `data bars` 的 `chart/tui` 默认大盘基准为 `000300.SH`，可通过 `--no-benchmark` 关闭。

运行前提：

- 配置文件路径：`~/.hiveflow/config.toml`
- 先启动 `quant` 服务，再运行本机 `cli`

最小配置：

```toml
server_url = "http://127.0.0.1:8000"
timeout_ms = 10000
retry = 1
```

## 9. 非目标（明确不做）

- 不做无审计的黑盒在线学习自动改参数。
- 不做跳过风控的“收益优先”执行。
- 不做不可复现的临时脚本上线。
